# Marketing team feedback — requirements

_2026-08-27_

The marketing team sent four requests. Each one is described below as a
requirement, not as a build plan.

## 1. Resources

A brand needs a **Resources** list. A Resource is a named external link that a
team member must find fast. The first example is a font website — the site
where the team buys or downloads the brand's typefaces. Other examples are
stock photo sites, icon libraries, and reference sites.

Each Resource holds a title, a URL, and an optional short note. The team groups
Resources by a type, so font links, image links, and tool links stay separate.
Each brand keeps its own Resources list. A Resource points to an external site;
the app does not store the file.

## 2. Photography

The **Photography** library needs sub-categories. The team splits photos by
subject — for example interior, food, people, and product. Each photo carries
one category, and the reader filters the library by that category. The category
set must be editable, because subjects differ per brand.

The team also pins the best photos. A pinned photo moves to the top of its
view, before the unpinned photos. The pin is a separate mark on the photo, not
the manual drag order the library already supports.

## 3. Marketing Funnel

The Marketing Funnel is both a map and a board.

As a map, it shows the brand's user journey as ordered stages. The default
stages are **Awareness, Interest, Consideration, Conversion, Loyalty, and
Advocacy**. Each stage is a block, and each block names the platforms that
serve it and links to them. The team edits the stages and the platform links
per brand — six stages is a starting template, not a fixed set.

As a board, each stage holds the activities the brand runs there now — for
example a campaign, a content push, or an influencer program. Each activity
names its platform, its status, and its dates. Each activity may link to a
record the app already holds — a social-calendar push, an influencer program,
or a contract; an activity with no link is plain text. The link makes the
funnel a hub: the team reaches the underlying work from the stage it serves.

The team uses the funnel to plan the next activities, to align on what is live,
and to track each activity's state. The funnel is the single view that answers
"what is this brand running, and where in the journey".

Tracking stays simple, not analytical. A status is a small set — for example
**Planned, Running, Paused, and Done**. The funnel records what runs and when;
it does not measure performance. The deep platforms measure performance.

## 4. Decks

A brand needs its decks on the brand profile. A **Deck** is a named brand
presentation — for example the Brand Deck, a Pitch Deck, or a Campaign Deck.
Each Deck belongs to one brand, and the brand profile lists the brand's decks.

A Deck holds an ordered stack of versions. Each version is one source — a PDF
file or an external link, usually Canva — with a version label, a date, and the
author. The newest version is the current one, and the brand profile shows it
by default. The team opens an earlier version from the Deck's history. A new
version supersedes the previous one; the team does not delete the old file to
add a new one. The stack records order, date, and author; it does not branch,
diff, or merge versions.

A Canva version snapshots on add. When the team adds a Canva link, the team
also attaches the PDF export of that moment. The link opens the live design;
the PDF preserves the snapshot the team saw when they added the version.
